Finding why an AI model got a covenant wrong, then fixing the rule

Result: Individual extraction failures became reusable rules, examples and validation controls instead of one-off corrections.

Read the case study

Typical failures: missing an exception, treating a carve-out as an inclusion, stopping at the main clause when a defined term held more of the answer.

Example. On a mandatory-prepayment field that needed every applicable basket, the model found one inclusion in the main clause and stopped, or returned a single basket when several applied. I traced its reasoning back to the source text, found the faulty stopping logic, added explicit rules for following defined terms and capturing all selections, gave one-shot examples, and reran the extraction to confirm the fix.

Controls added. Field validation so percentage and dropdown fields only accepted valid values. Reconciliation of manual research against a consolidated master dataset. Sanity checks that blocked data transfer when required conditions failed.

Why "excluding" is the costliest word in a debt basket

A cap of the greater of a fixed amount and a percentage of EBITDA reads cleanly. Then a parenthetical removes ratio debt from the count, and a separate section removes more. An extraction that reads only the main clause overstates capacity.

The fix is procedural: trace the definition, the parentheticals and the separate exclusions before deciding the final treatment.

When an AI model stops at the first answer

In a clause that needs every applicable basket, one inclusion in the main clause can end the search while a defined term elsewhere holds the rest. Reading the model's reasoning against the source shows where it stopped.

The fix is a rule, such as follow defined terms and capture every selection, plus one example. It is not a patch for a single document.
